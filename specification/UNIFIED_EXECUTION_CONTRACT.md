# Psychohistory 2.4 — Unified Execution Contract

Status: versioned integration extension derived from the recovered 2.0–2.4 corpus and the canonical 2.4 volumes. This document does not retroactively alter frozen forecasts or claim empirical validation.

## 1. Purpose

Psychohistory is executed as a federation of mathematical models, diagnostic algorithms, sidecars and counter-models. Modules are not selected because they support a desired narrative. Every registered module is evaluated whenever its input contract is applicable. A module may return a null, unresolved, unavailable, contradictory or non-predictive result.

The system is therefore not a news summariser and not a consensus-voting engine.

## 2. Canonical execution graph

Point-in-time observations
→ measurement/vintage validation
→ Evidence Ancestry Graph
→ M/P/E/I/L state representation
→ independent algorithm family execution
→ sidecar/domain execution
→ disagreement/dependence graph
↔ inverse-source inference
↔ propagation/response graph
→ historical anchors + counter-anchors
→ admission gates
→ baseline comparison
→ Stage A/B prediction
→ calibration
→ immutable forecast ledger
→ outcome resolution
→ scoring
→ model/sidecar diagnostic feedback.

Feedback may alter future registered models only through a new version. It cannot rewrite a frozen forecast.

## 3. Required independent algorithm families

The run registry includes G1 memetics/point processes, G2 stochastic stability, G3 network/spectral inference, conditional G23 coupling, dependence/surrogate tests, sequential detectors, historical recurrence/anchors, stochastic counter-models and every registered sidecar/domain model.

These modules remain mathematically distinct. Agreement does not make them independent evidence when ancestry is shared.

## 4. Required sidecars

At minimum the recovered corpus registers BADL/BADL-M, GISC, CTSC, TPSS, IISC, CCSC and SCFS. Candidate domain models include infectious disease, banking/lending/property, gold, pensions, arts/cultural activity and disability hostility/violence where an Outcome Contract makes them applicable.

No sidecar is silently omitted.

## 5. Module state vocabulary

Each module must return one of:

ACTIVE
ZERO_EVIDENCE
UNAVAILABLE
INVALID
REDUNDANT
DEPENDENT
NOT_APPLICABLE
WEAKLY_IDENTIFIED
UNRESOLVED
DIAGNOSTIC_ONLY
ADMITTED

Missing output is a pipeline failure, not a neutral result.

## 6. Disagreement is first-class data

For comparable outputs i,j, preserve D_ij rather than averaging it away. The disagreement layer records direction, magnitude, persistence, ancestry overlap, horizon compatibility and whether disagreement is expected under the models.

A disagreement may be predictive, diagnostic, misspecification, scale mismatch or unresolved. It is never automatically evidence of hidden causation.

## 7. Bidirectionality

Forward inference:
cause/state candidate → propagation → domain response → outcome distribution.

Inverse inference:
observed response geometry → candidate sources → ranked source posterior.

Prediction feedback:
resolved outcome → proper score/diagnostic → module performance history → future admission/demotion decision.

The outcome may update future model status only after resolution and according to the registered validation protocol.

## 8. Expected-but-absent propagation

For every registered propagation hypothesis, the system records both observed propagation and expected-but-absent propagation. Failure of a predicted transmission path is evidence against that path/model and is retained.

## 9. No narrative override

News, analyst commentary and model-generated prose are observations or contextual metadata only. They cannot override mathematical outputs, change weights after seeing an outcome, suppress disagreeing modules, or create an unregistered causal edge.

## 10. Prediction gate

A forecast labelled integrated Psychohistory requires:

WorldStateEvaluated
AND AllApplicableModulesReported
AND EvidenceAncestryResolved
AND DependenceAndMultiplicityRecorded
AND DisagreementsPreserved
AND BaselinesComputed
AND OutcomeContractFrozen
AND InformationSetPointInTime
AND CalibrationStatusDeclared.

Failure of any required condition yields UNRESOLVED or DEVELOPMENT_ONLY rather than an integrated forecast.

## 11. Validation rule

A side equation may remain valuable as a diagnostic or counter-model even if it is not an admitted predictor. Predictive contribution and diagnostic/disagreement contribution are evaluated separately. No component receives positive predictive weight merely because it exists.

## 12. Reporting rule

Machine output precedes narrative explanation. Reports expose module statuses, nulls, disagreements, dependencies, missing data, uncertainty, baseline comparison and empirical status before interpretation.
